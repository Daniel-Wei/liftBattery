# liftBattery 产品定位与首版范围

更新日期：2026-10-20。

liftBattery 是面向备赛私教的学员管理平台，帮助教练统一管理学员档案、备赛进度、线下课程、训练执行与营养摄入，让每次授课和每周复盘都有连续记录。

已确认的方向是线下私教为主、备赛为核心，复用现有个人训练记录，并增加蛋白质、碳水化合物和脂肪摄入记录。首版暂按健美／健体备赛场景设计。

本轮执行范围为教练端 UI 与本机工作区：工作台和排课页嵌入同一套日历，教练维护学员档案、备赛、课程课时、营养体重及周复盘。暂不增加学员自助记录或个人端。保持现有暗蓝／青色视觉主题，现有个人记录、报告及完整 3D 模型功能不得删减。多学员云端 API、账户关系授权和同步属于后续范围；下文同时描述目标流程，不能据此认定服务端已实现。

## 服务对象与核心价值

- 核心客户及拟付费方：直接带备赛学员的独立私教。首版围绕一名教练管理多名学员，不先扩展健身房员工、门店和销售管理。
- 教练：建档、安排备赛计划与课程、代录训练、管理课时、检查每日执行、留下复盘与调整。
- 学员：本轮作为教练管理的档案对象；查看目标、自助记录或提交反馈的学员端暂缓。
- 核心价值：教练打开平台就知道今天教谁、谁需要跟进、当前备赛计划执行得怎样；学员知道今天要做什么、实际完成了什么。

教练是本轮唯一新增工作台角色，可直接建立学员档案，不依赖学员账户。邀请与绑定流程待引入学员端时实现。

## 首版工作流程

1. 教练建立学员档案，记录目标、基础情况、比赛名称／日期、项目及当前备赛阶段。
2. 教练安排训练、有氧和每日营养目标，记录本周重点与下次复盘日期。
3. 教练排线下课程，关联学员及课包；授课时查看上次训练并记录本次实际完成情况。
4. 课程确认完成后扣减课时，训练记录关联这次课程。课外自主训练单独保存，不自动扣课。
5. 教练登记每日三大营养素、体重和恢复情况，并整理授课观察。
6. 教练对照目标、实际摄入、体重趋势和训练表现完成周复盘，记录下一阶段调整及其生效日期。

## 首版核心功能

| 模块 | 首版内容 | 教练需要回答的问题 |
|---|---|---|
| 学员档案 | 学员列表、目标、服务状态、教练备注、账户邀请与绑定 | 我在带谁，当前目标是什么？ |
| 备赛管理 | 比赛与日期、备赛阶段、距比赛周数、训练／有氧／营养目标及调整历史 | 每个学员目前处在哪个阶段？ |
| 排课与课时 | 预约、改期、取消、完成；课包、剩余课时和扣课流水 | 今天有哪些课，还剩多少课？ |
| 训练执行 | 复用动作、角度、组次、重量、RIR、热身组及前后次对比；关联计划和课程 | 计划是否完成，表现有什么变化？ |
| 每日备赛记录 | 教练登记三大营养素实际摄入、体重；区分未填与已填 | 实际执行与目标差在哪里？ |
| 周复盘 | 固定条件的进度照片、学员反馈、教练点评和下一步安排 | 这一周发生了什么，下周调整什么？ |

### 三大营养素记录

营养记录按学员和当地日期独立保存，覆盖训练日与休息日，不依附某一次训练或练前检查。

| 字段 | 单位 | 来源 |
|---|---|---|
| 蛋白质目标／实际摄入 | g／天 | 目标由教练设置，实际由学员或教练录入 |
| 碳水化合物目标／实际摄入 | g／天 | 同上 |
| 脂肪目标／实际摄入 | g／天 | 同上 |
| 体重 | kg | 每日记录，可标注称重条件 |
| 饮食执行备注 | 文本，可选 | 外食、漏记或其他影响本次记录的情况 |

- 首版直接填写每日总克数；热量可由三大营养素估算并明确标注。食物数据库、拍照识餐、扫码及逐餐食谱不作为首版依赖。
- 教练可以为训练日、休息日指定不同目标，或设置指定日期的目标；自动碳循环和自动营养处方不属于首版。
- 目标按生效日期保留版本。修改下周目标不能改写上周对比所用的目标。
- 缺失值与零摄入不同；部分填写必须显示为不完整，不能将未填视为达标或未达标。
- 日视图显示目标、实际值及差额；周视图显示有记录天数、已记录日的摄入趋势及同期体重变化，不把漏记当作低摄入。
- 教练以实际记录和学员反馈作出调整。系统负责展示和提醒，目标发布由教练确认。

### 线下课程与课时

- 预约与训练是不同记录：一次预约可以关联训练执行，单独填写训练不代表已授课。
- 课包维护购课、扣课和冲正流水，余额由流水计算。完成课程只能扣课一次；修改训练组数不能再次扣课。
- 预约未完成不扣课。取消、缺席或撤销已完成课程需显式选择是否扣课或返还，并保留原因。
- 首版人工登记课包和收款状态；在线支付、财务核算和门店经营后续再评估。

### 备赛进度与周复盘

备赛阶段由教练指定，可包括增肌／准备、减脂备赛、赛前周、赛后恢复；具体阶段名称与时间可调整。比赛倒计时、阶段目标、执行记录和周复盘共享同一条时间线。

进度照片按日期及正面、侧面、背面等视角归档，提示尽量使用一致的拍摄条件；照片用于教练复盘，不自动给出体脂或上台状态结论。备赛指标采用记录、算术对比或标明依据的观察信号，沿用项目现有的证据边界。

## 两端页面组织

| 教练端 | 主要内容 |
|---|---|
| 工作台 | 今日课程、待查看打卡、待复盘学员、临近比赛和课时不足提示 |
| 学员 | 档案列表；详情内含备赛、课程／课包、训练、营养／体重、恢复及周复盘 |
| 日历 | 排课、改期、取消、完成课程 |
| 计划模板 | 复用训练安排与营养目标，分配后保留学员自己的版本 |
| 复盘 | 待审核周反馈、历史点评和计划调整 |
| 设置 | 教练资料、基础偏好及邀请管理 |

学员端暂缓。已有个人训练工具保持独立入口，3D 动作指引保持完整独立导航和工作台快捷入口。

## 现有系统的复用与缺口

| 现有能力 | 新定位中的用途 | 需要补充的能力 |
|---|---|---|
| 用户与 cookie 登录 | 教练／学员登录基础 | 教练工作区、学员档案、邀请绑定及关系授权 |
| 训练记录与每日对比 | 学员训练历史、教练代录及授课复盘 | 计划目标、课程关联、录入者与修改记录 |
| PreCheck | 每日恢复记录及授课前参考 | 教练查看所属学员；沿用真实持久化字段，扩展字段单独实现 |
| 趋势与周报 | 学员备赛复盘的汇总材料 | 营养、体重及计划执行数据源，教练批注和授权访问 |
| 动作指引 | 计划和训练记录中的辅助信息 | 调整入口位置 |
| 原 NutritionEntry／BodyweightEntry 类型 | 营养和体重的数据命名参考 | 新教练营养页面与本机记录已实现；服务端 API、持久化和云端关系授权仍需新增 |
| 本地 ProgramSettings | 旧个人周期设置参考 | 可跨设备读取、可按学员分配且保留版本的服务端备赛计划 |

现有训练、恢复和报告数据继续属于原用户，不能因为登录者被设置成教练就自动把历史记录变成某个学员的数据。已有账户如何绑定学员档案需要显式确认。

教练端每个读写请求都必须验证有效的教练与学员关系；仅让前端传入学员 ID 不构成授权。报告文件、进度照片和下载链接遵守同样的访问边界。

## 实施顺序与验收

1. 建立教练工作区、学员档案、账户绑定与服务端访问隔离，先保证教练可以安全切换所带学员。
2. 建立学员的备赛日期、阶段和目标；复用训练与 PreCheck，补齐每日三大营养素及体重的端到端保存。
3. 建立排课、课包流水及课程与训练的关联，完成线下授课闭环。
4. 建立周反馈、照片、教练复盘和工作台，再将新数据纳入现有报告。

首版验收用同一名教练与至少两名学员走通：建档、备赛目标、排课、完成并扣课、记录训练与三大营养素、对比历史、周复盘和调整目标；同时验证学员之间、不同教练之间的数据隔离及重复完成课程不会重复扣课。

试用时记录教练完成一次周复盘所需时间、实际管理的活跃学员数、每日打卡完整率和课时纠错情况。用真实使用反馈决定后续功能优先级，不把更多图表或页数当作产品进展。

## English summary

liftBattery is a client management platform for personal trainers who coach physique competition preparation, with in-person training as the first delivery model. Coaches manage client profiles, competition timelines, appointments, session credits, training execution, daily protein/carbohydrate/fat intake, bodyweight and weekly reviews.

Existing personal training, readiness and reporting modules will be reused with explicit coach-client authorization. Nutrition and bodyweight currently have placeholder frontend types only; complete daily logging and persistence are new requirements. Coaches own plan decisions, while clients use a lightweight mobile interface to view targets and submit records.
